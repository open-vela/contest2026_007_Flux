# InfoPlat 信息台

## 一、作品简介

InfoPlat 信息台是一款基于 openvela 系统构建的轻量级信息聚合平台，面向 RTOS 环境下的智能设备，提供新闻、天气、快递等常用信息的统一获取与展示。项目充分利用 openvela 系统提供的多种原生能力，在资源受限的嵌入式平台上实现了完整的信息流转闭环。

**解决的问题：** 当前 RTOS 平台缺乏开箱即用的信息聚合解决方案，开发者通常需从零构建网络请求、HTML 解析、UI 渲染等基础链路。InfoPlat 提供了完整、可复用的信息聚合框架，填补了这一空白。

**亮点：**
- 深度整合 openvela 系统能力（fetch/prompt/storage）
- 自研 Tecko Reader 引擎，纯本地 HTML 正文提取
- AI-Native 开发工作流，AI 代码占比 >85%
- 与 openvela 及 Rivotek 团队协作解决底层技术问题

## 二、选题方向

## 四、运行方式

### 环境准备
1. 安装 Node.js >= 8.10
2. 安装 aiot-toolkit：`npm install -g aiot-toolkit`
3. 准备 openvela 开发环境（参考官方文档）

### 开发调试
```bash
# 进入快应用目录
cd quickapp/hello_quickapp

# 安装依赖
npm install

# 启动开发服务器
npm run start
```

### 构建打包
```bash
# 构建项目
npm run build

# 打包发布
npm run release
```

### 部署到设备
1. 使用 aiot-toolkit 连接模拟器或真机
2. 扫码或手动安装快应用包
3. 在目标设备上启动"信息台"应用

## 五、AI Coding 使用说明

### AI-Native 开发工作流
本项目全程采用 AI-Native 开发模式，以"功能驱动 + 问题驱动"为核心方法论：

#### 5.1 启动阶段：代码通读
每轮开发会话启动时，首先向 AI 助手下达代码通读指令，确保 AI 在充分理解现有代码结构的基础上开展后续工作。

#### 5.2 开发迭代：双驱动模式
- **问题修复驱动**：描述问题现象与复现路径，提供相关代码片段，交由 AI 自主阅读并定位分析根因，提出修复方案
- **新功能驱动**：要求 AI 编写功能计划书，内容涵盖实现方式、涉及文件与代码布局、对其他模块的影响范围、潜在风险及应对策略，计划书经人工审核修正后方可交由 AI 编码实现

#### 5.3 Skills 工具使用
项目充分利用 openvela 提供的打包 Skill，实现了项目源码的一键打包、部署及 IMG 镜像包的自动生成，大幅简化了构建与发布流程。

#### 5.4 AI 代码占比与 Token 消耗
- **AI 编写代码占比**：>85%，人类开发者从重复编码中解放，重心转向产品定义、方案设计与创新思考
- **累计 Token 消耗**：约 6.18 亿 Token

### AI 带来的帮助
- **开发效率提升**：快速生成基础代码框架，减少重复工作
- **代码质量改善**：AI 提供最佳实践建议和代码审查
- **学习曲线降低**：通过 AI 解释快速理解框架特性和 API 用法
- **问题解决加速**：AI 协助分析错误日志和调试信息

### 完整对话日志
详细的 AI Coding 对话记录见 `logs/` 目录，包含了从项目初始化到功能完成的完整开发过程。

## 六、技术亮点

### 6.1 openvela 系统能力应用
| 系统能力 | 应用场景 |
|---------|---------|
| fetch | 实现新闻、天气、快递等信息的联网获取与数据拉取 |
| prompt | 构建用户交互过程中的弹窗提示与信息确认机制 |
| storage | 完成用户偏好设置、历史记录等数据的本地持久化存储 |

### 6.2 自研 Tecko Reader 引擎
在无 WebView、无 JavaScript 的纯 RTOS 环境下，自主实现了新闻 HTML 页面的正文提取与广告过滤：

| 模块 | 功能说明 |
|-----|---------|
| BSC 基础评分模块 | 综合中文密度、文本长度、句末标点等特征计算行文得分 |
| extractP 文本提取 | 基于评分结果提取高质量文本段落 |
| structFilter 结构过滤层 | 过滤非正文 DOM 结构与噪音节点 |
| LQB 连续低谷计数 | 识别并跳过正文中的低信息密度区间 |
| adTTL 广告判别层 | 对疑似广告内容进行评分熔断，精准滤除推广信息 |
| scoreFusion 分数融合层 | 融合多维评分结果，输出综合置信度 |
| SPIM 短段落分数扭转 | 对短段落进行分数修正，避免有效信息被误滤除 |

**技术价值：** 该方案证明，在 RTOS 这类计算资源与内存资源严重受限的环境下，依然可以实现高质量、高纯度的新闻正文提取，为嵌入式信息聚合类应用提供了可行的技术范式。

### 6.3 技术优化与问题解决
与 openvela 开发团队及 Rivotek（润芯微）开发团队密切协作，共同定位并解决了一系列底层技术问题：
1. **Makefile 编译问题**：修复了编译过程中头文件缺失导致的构建中断问题
2. **LVGL 显示适配**：解决了 LVGL 图形库在目标平台上的渲染异常
3. **CA 证书验证问题**：修复了 HTTPS 请求中证书校验失败的网络通信障碍

## 七、总结

InfoPlat 信息台是 openvela 系统在 RTOS 信息聚合场景下的一次完整实践验证。项目充分调用 openvela 系统能力，结合 AI-Native 开发工作流高效交付，自研 Tecko Reader 引擎更在资源受限环境下实现了突破性的纯本地 HTML 内容提取方案。我们期望本项目能为后续 openvela 开发者提供有价值的参考范例，也期待系统生态的持续演进。
